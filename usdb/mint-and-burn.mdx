---
title: Mint and burn
description: Convert between USD and USDb (Rootstock).
---

Minting converts a company's USD into USDb. Burning reverses the conversion,
turning USDb back into USD. Both operations move funds between two of the
company's own wallets.

## Before you start

Before a company can mint or burn, it must:

- Have completed full KYC.
- Have an **active** USD wallet.
- Have an **active** USDb wallet on the `ROOTSTOCK` rail.

If any requirement is missing, mint and burn requests are rejected. You will
need the `id` of both wallets, which you can get from
[List wallets](/usdb/balance-accounts#list-wallets).

All mint and burn requests:

- Use **API key authentication** only.
- Require an `Idempotency-Key` header.
- Take an `amount` in **major units** as a string (for example `"100.00"`),
  with a minimum of `10`.

## Mint USDb

Move USD from the company's USD wallet and receive USDb in its
USDb (Rootstock) wallet.

- `from_account_id` — the USD wallet
- `to_account_id` — the USDb wallet (Rootstock)

```bash
curl -X POST "https://api.sandbox.bitwage.com/api/wallets/mint" \
  -H "Authorization: Basic YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 8f3c1e90-0c2a-4b7e-9a1d-2b6f0e2c1a44" \
  -d '{
    "company_id": "2312332124124",
    "from_account_id": "custodial_account_usd",
    "to_account_id": "custodial_account_usdb",
    "amount": "100.00"
  }'
```

```json Response
{
  "status": "initiated"
}
```

## Burn USDb

Move USDb from the company's USDb (Rootstock) wallet and receive USD in its
USD wallet.

- `from_account_id` — the USDb wallet (Rootstock)
- `to_account_id` — the USD wallet

```bash
curl -X POST "https://api.sandbox.bitwage.com/api/wallets/burn" \
  -H "Authorization: Basic YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 1b9d6f22-5e3a-4c81-bf0e-7a2c4d1e9f33" \
  -d '{
    "company_id": "2312332124124",
    "from_account_id": "custodial_account_usdb",
    "to_account_id": "custodial_account_usd",
    "amount": "100.00"
  }'
```

```json Response
{
  "status": "initiated"
}
```

## What happens next

Mint and burn requests are processed **asynchronously**. The API acknowledges
the request immediately, then settles the conversion in the background. A
`status` of `initiated` means the conversion was accepted and is settling. When
it finishes, Bitwage sends a
[`wallet.mint` or `wallet.burn` webhook](/usdb/webhooks) with the final status
and the underlying transaction details.

<Note>
A successful mint or burn response only confirms that the request was
**accepted**, not that funds have moved. Wait for the corresponding
`wallet.mint` or `wallet.burn` webhook before treating a conversion as
complete, rather than polling.
</Note>

<Warning>
Do not retry a mint or burn with a new idempotency key just because the
response has not arrived. Reuse the same `Idempotency-Key` to safely retry —
a replay returns the original result without converting funds twice.
</Warning>

## Errors

| Code | Meaning |
|---|---|
| `custodial-below-minimum` | The amount is below the `10` minimum. |
| `custodial-insufficient-balance` | The source wallet does not have enough balance. |
| `custodial-invalid-from-currency` | The source wallet is not the expected currency for this operation. |
| `custodial-invalid-from-rail` | The source wallet is on the wrong rail. |
| `operational-wallets-not-found` | The company is not provisioned for USDb mint/burn. |
