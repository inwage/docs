The Bitwage Partner API uses REST conventions with JSON request and response
bodies. All endpoints are authenticated using either API key (Basic auth) or
OAuth 2.0 bearer tokens.

## Base URL

```
https://api.sandbox.bitwage.com   # Sandbox
https://api2.bitwage.com          # Production
```

## Authentication

All API endpoints require authentication. Include your credentials in the
`Authorization` header:

- **API Key**: `Authorization: Basic <ACCESS_TOKEN>`
- **OAuth 2.0**: `Authorization: Bearer <ACCESS_TOKEN>`

See the [Authentication guide](/guides/authentication) for setup instructions.

## Errors

The API returns standard HTTP status codes and a JSON error body:

```json
{
  "request_id": "5f1d1c2e-4f0a-4b53-9d0e-6d0f6f8f2a11",
  "message": "Human-readable error description",
  "code": "stable-error-code",
  "data": { "retryable": false }
}
```

Branch on `code`, not `message`. Validation errors (`422`) add a `schema`
object with the failing fields. A few older `/api/user/*` endpoints return
`{"error": "..."}` instead.

| Status | Description |
|---|---|
| `200` | Success |
| `400` | A business rule rejected the request. Check `code` and `data.retryable`. |
| `403` | Invalid credentials, missing permission, or a resource you don't own. Authentication failures are `403`, not `401`. |
| `404` | Not found |
| `409` | The resource is in an incompatible state |
| `422` | Validation error. See `schema`. |
| `500` / `502` | Unexpected or downstream error. Retry with the same `Idempotency-Key`. |

See the [Errors guide](/guides/errors) for every error code by endpoint and how
to retry safely.
